# Architecture rules

## Where code goes

| Place | Holds | Example |
| --- | --- | --- |
| `src/routes/` | Every page. TanStack file routes. Page components are written here, not in modules | `routes/sales-orders.new.tsx` |
| `src/modules/<feature>/` | Code that belongs to one business feature | `modules/customers/components/customer-sheet.tsx` |
| `src/components/erp/` | Shared app components used by more than one page | `data-table.tsx`, `page-header.tsx` |
| `src/components/layout/` | The app shell only: sidebar, header, command menu, theme toggle, nav | `nav.ts` |
| `src/components/ui/` | shadcn/ui components. Generated, do not hand-edit | `button.tsx` |
| `src/db/` | Drizzle schema, connection, seed | `schema.ts` |
| `src/lib/` | Pure helpers: formatting, validation, shared constants | `format.ts` |
| `src/hooks/` | shadcn hooks (`use-mobile`, `use-highlighted-code`) | |

## Rules

1. A module is a business feature, never a UI layer. Layout and shared UI are not modules.
2. Each module has `server.ts` (server functions), `types.ts` (Zod schemas and their inferred types), and `components/` (feature-only UI). Add a `hooks/` folder only when a hook is reused by two or more places.
3. Routes import from modules. Modules never import from routes.
4. Modules import from other modules only through their `server.ts` or `types.ts`. Reuse a shared component from `components/erp/` instead of importing another module's component.
5. No barrel files (`index.ts` that re-exports). Import the file that defines the thing.
6. `src/components/ui/` is generated by the shadcn CLI. Change behaviour by composing components in your own code, not by editing them. If you must edit one, say why in the PR.
7. Path alias `@/` points at `src/`. Use it instead of long relative paths.

## Why

Features stay easy to find and delete. A new engineer can open `src/modules/vendors/` and see everything about vendors in one place. See [Decision 0003](../decision/0003-module-driven-structure.md).
